# depgraph

Инструмент командной строки для визуализации графа зависимостей пакетов
NuGet (.NET). Написан на Python 3 только на стандартной библиотеке: менеджеры
пакетов и сторонние библиотеки для получения зависимостей не используются.

## 1. Общее описание

Параметры работы задаются опциями командной строки. На текущем этапе
(этап 2, сбор данных) инструмент обращается к репозиторию NuGet по протоколу
V3 (`index.json`) и печатает прямые зависимости заданной версии пакета.
Запросы выполняются стандартным `urllib`, манифест пакета (`.nuspec`)
разбирается стандартным `xml.etree`.

Требуется Python 3.10 или новее.

## 2. Описание функций и настроек

### Опции командной строки

| Опция               | Обяз.        | Описание                                                    |
|---------------------|--------------|-------------------------------------------------------------|
| `--package`         | да           | Имя анализируемого пакета                                   |
| `--repo`            | да           | URL-адрес репозитория NuGet или путь к файлу тестового репозитория |
| `--repo-mode`       | нет          | Режим работы с репозиторием: `remote` (по умолчанию) или `test` |
| `--package-version` | в `remote`   | Версия пакета                                               |
| `--ascii-tree`      | нет          | Вывести зависимости в формате ASCII-дерева                  |
| `--max-depth`       | нет          | Максимальная глубина анализа, 0..500 (по умолчанию 3)       |
| `--filter`          | нет          | Не учитывать пакеты, имя которых содержит подстроку         |

Режимы `--repo-mode`:

* `remote` - `--repo` является URL-адресом сервиса NuGet V3
  (например, `https://api.nuget.org/v3/index.json`);
* `test` - `--repo` является путём к файлу тестового репозитория.

### Обработка ошибок

При неверном параметре печатается сообщение `Ошибка: ...` в поток ошибок,
код завершения процесса равен 2. Проверяются: наличие имени пакета и его
формат (идентификатор NuGet либо заглавные латинские буквы в тестовом
режиме), формат URL, существование файла тестового репозитория, допустимое
значение режима, формат версии, целочисленность и диапазон глубины, отсутствие
пробельных символов в подстроке фильтрации, неизвестные опции.

### Как собираются зависимости (этап 2)

1. Из `--repo` (адрес службы `index.json`) берётся адрес ресурса
   `PackageBaseAddress`.
2. Версия приводится к нормализованному виду (`1.0` -> `1.0.0`), имя и
   версия переводятся в нижний регистр, скачивается
   `{base}/{id}/{version}/{id}.nuspec`.
3. В манифесте читаются элементы `dependency` всех групп `group` (целевых
   платформ). Зависимости разных платформ **объединяются** по имени пакета
   (имена не зависят от регистра), диапазон версий берётся из первой группы,
   где пакет встретился. Так сделано потому, что целевая платформа не входит в
   список параметров инструмента.
4. Диапазон версий зависимости разрешается в конкретную версию так же, как
   это делает NuGet: берётся наименьшая версия репозитория, подходящая под
   диапазон (`NuGetRepository.resolve_version`). Пререлизы учитываются,
   только если нижняя граница диапазона - пререлиз.

Вывод: имя зависимости, диапазон версий из манифеста и список платформ
(показаны три первые, остальные сворачиваются в «и ещё N»).

Ошибки получения данных (нет сети, пакет или версия не найдены, ответ
службы не JSON, повреждённый `.nuspec`) печатаются как `Ошибка: ...`, код
завершения 1.

### Модули

* `src/depgraph/config.py` - разбор и проверка параметров (`parse_config`);
* `src/depgraph/cli.py` - точка входа (`main`), вывод зависимостей;
* `src/depgraph/nuget.py` - клиент NuGet V3 (`NuGetRepository`);
* `src/depgraph/nuspec.py` - разбор `.nuspec` (`parse_dependencies`);
* `src/depgraph/versions.py` - версии и диапазоны версий NuGet;
* `src/depgraph/errors.py` - исключения репозитория.

## 3. Сборка, запуск и тесты

Сборка не требуется. Запуск:

```sh
./run.sh --package Serilog --repo https://api.nuget.org/v3/index.json \
         --package-version 3.1.1
make run ARGS="--package A --repo tests/data/simple.txt --repo-mode test"
```

Тесты (стандартный `unittest`) и проверка стиля (`flake8`):

```sh
make test
make lint
```

## 4. Примеры использования

```console
$ ./run.sh --package Serilog.Sinks.File \
           --repo https://api.nuget.org/v3/index.json --package-version 5.0.0
Прямые зависимости пакета Serilog.Sinks.File 5.0.0 (1):
  Serilog 2.10.0  [платформы: .NETFramework4.5, .NETStandard1.3, net5.0 и ещё 2]
```

```console
$ ./run.sh --package NoSuchPackageXyz \
           --repo https://api.nuget.org/v3/index.json --package-version 1.0.0
Ошибка: пакет 'NoSuchPackageXyz' версии 1.0.0 не найден в репозитории
```

```console
$ ./run.sh --package A --repo no_such_file.txt --repo-mode test
Ошибка: файл тестового репозитория 'no_such_file.txt' не найден
```
